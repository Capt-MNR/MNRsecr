Permission note:
If straightforward, add an explicit grant_reason/purpose field to permissions so the model supports Who + What + Why + Scope + Duration. Do not redesign the permission system beyond the approved foundation.

Important security constraints:

- Never trust tenant_id or user_id from request body/model output.
- Never allow the model to grant or broaden permissions.
- Never expose Supabase service-role credentials to clients or models.
- Do not use graph relationships as access permissions.
- Do not introduce new polymorphic Context Graph links.
- source_type/source_id may remain only where explicitly designed as provenance/audit/event metadata and must never bypass RLS.
