==================================================
GLOBAL RULE
==================================================

For every FAIL scenario:

1. Inspect the actual Brain/runtime path.
2. Compare actual behavior against the exact Evaluation Contract.
3. Determine the root cause.
4. Classify it as one of:

A. REAL_BRAIN_DEFECT
B. REAL_EXISTING_SUBSYSTEM_DEFECT
C. EVALUATOR_DEFECT
D. CONTRACT/EVALUATOR_MISMATCH
E. FIXTURE/ENVIRONMENT_PROBLEM
F. EXPECTED_BEHAVIOR_REQUIRES_REVIEW

Then apply this rule:

IF A or B:
    implement the smallest safe fix.

IF C:
    fix the evaluator only if objectively incorrect.

IF D:
    DO NOT change implementation to satisfy the mismatch.
    Preserve the agreed Evaluation Contract and document the mismatch.

IF E:
    do not fake the fixture or result.
    Improve the test seam only if it is clearly required and isolated.

IF F:
    do not make speculative product changes.
    Document the ambiguity and leave implementation unchanged.

After every actual fix:
- run the relevant focused tests
- run the Brain evaluation
- verify no regression

Do NOT make speculative changes merely because a scenario failed.

L0–L3 POLICY
==================================================

Treat L0–L3 as required intelligence levels, not model names.

L0:
Deterministic/structured behavior is sufficient.

L1:
Lightweight interpretation is required.

L2:
Contextual reasoning across relevant sources is required.

L3:
Deep synthesis/planning is required.

IMPORTANT:

Do not force the system to use L0 merely to reduce LLM usage.

If the existing implementation uses L2 where L0 is contractually expected, determine whether:
- the Brain actually selected L2,
- the evaluator inferred L2,
- or the underlying runtime behavior is actually reasoning-heavy.

Only change it if the contract and runtime evidence clearly establish a defect.

The product principle remains:

LLM-first for intelligence,
deterministic-first for execution and safety.

Do not optimize away reasoning that materially improves the Secretary.

==================================================

- do not blind retry.

- affect only the latest appropriate pending operation in the same conversation.
- never alter completed/executing/expired operations improperly.

If verification fails:
- preserve uncertainty.
- reconcile safely.
- avoid duplicate mutation.
